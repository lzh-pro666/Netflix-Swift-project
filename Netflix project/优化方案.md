# 短视频播放模块全面优化方案 v1.0（基于现有 Texture + ASCollectionNode + AVPlayer 架构）

本方案在充分理解现有代码与运行表现基础上，给出一套从架构到实现可直接落地的优化方案，目标是：显著提升滑动与播放流畅度、降低功耗、统一进度条与拖动体验、杜绝复用与观察者泄漏问题，并为后续功能扩展（预加载、打点、无缝切换、PIP 等）打下稳定基础。

----------------------------------------

1) 目标与收益

- 体验一致：所有 Cell 在进入可见时进度条与播放行为一致，拖动不跳回、不卡顿。
- 性能提升：
  - 滑动 FPS 接近系统上限（> 55fps，低端机 > 45fps）。
  - 首帧显示时间下降 20%+（以 pool 复用与预热实现）。
  - CPU/GPU 平均占用下降，掉帧显著减少。
  - 内存稳定、无观察者泄漏。
- 工程可维护：清晰的模块边界与生命周期、统一的观察者管理、可回滚的渐进迁移。

----------------------------------------

2) 现状与主要问题清单

- Player 粒度：每个 Cell 独立 AVPlayer 与回调，导致多路解码、资源争用、功耗高。
- 进度条方案：UISlider 嵌入 Texture，UIKit 与异步渲染桥接带来额外主线程开销与层级复杂度。
- 进度回调频率：固定 0.25s（≈4Hz），视觉不够平滑；拖动/不可见时未节流或暂停，存在冗余开销。
- Seek 并发：没有系统性的并发防护，拖动中多次 seek 可能互相覆盖，出现回到 0s 或跳动。
- 观察者管理：KVO 与 timeObserver 清理分散，Cell 复用/退出时存在遗漏风险。
- 生命周期：didEnterVisibleState/didExitVisibleState 与复用边界没有统一协调，容易出现播放状态污染。
- 预加载：策略缺失或不稳定，影响弱网与下一条首帧体验。

----------------------------------------

3) 总体架构设计（组件与职责）

- VideoPlayerPool（核心）
  - 全局最多 2 个 AVPlayer：1 主播放器（active），1 预热播放器（warmup）。
  - 负责将 AVPlayerLayer 与当前可见 Cell 进行绑定/解绑，主线程执行 attach。
  - 统一管理 add/remove timeObserver，避免多处重复订阅。

- PlaybackCoordinator（协调器）
  - 仅对当前 active Cell 开启高频进度回调（约 15fps）。
  - 负责播放/暂停、拖动时的状态冻结与恢复，节流 UI 更新。
  - 管理 generationToken，丢弃过期异步回调，防止竞态。

- ProgressNode（自绘进度条）
  - 用 ASDisplayNode 自绘背景、缓冲、已播放进度，轻量且异步绘制友好。
  - 手势驱动（UIPan 或 ASControlNode 触摸事件），产生 0~1 的进度回调供 Coordinator 进行 seek。
  - 拖动中视觉反馈（高度/颜色）与拖动结束后的 seek 对齐。

- PreloadManager（可选增强）
  - 按触发条件（播放 ≥ 60% 或 ≥ 1s）预热下一条视频（创建 AVURLAsset，loadValuesAsynchronously）。
  - 快速滑动时取消/降级预载，避免带宽与磁盘竞争。

- ObserverCenter（实现细节）
  - 统一保存 NSKeyValueObservation 与 timeObserver token，提供显式生命周期（attach/detach）。

4) 关键模块设计与接口（示例骨架）

说明：以下为关键接口骨架，真实实现需按现有目录与代码风格接入。

4.1 VideoPlayerPool（单例）

- 属性：
  - mainPlayer: AVPlayer（active）
  - warmupPlayer: AVPlayer（预热）
  - activeItemToken: UUID（绑定当前 item 的 generationToken）
  - timeObserver: Any?（仅对 mainPlayer）
- 主要方法：
  - attach(item: AVPlayerItem?, to layer: AVPlayerLayer, mute: Bool)
  - play() / pause()
  - addPeriodicObserver(fps: Int, callback: @escaping (CMTime) -> Void)
  - removePeriodicObserver()
  - prepareNext(asset: AVURLAsset, completion: @escaping (Result<AVPlayerItem,Error>) -> Void)

关键要点：主线程 attach；replaceCurrentItem 前 cancelPendingSeeks；对回调与 item 绑定 token，切换时立即失效旧 token。

4.2 ProgressNode（ASDisplayNode）

- 属性：progress(0~1)、bufferedRanges、isDragging。
- 事件：onBeginDrag()、onChange(pct: Double)、onEndDrag(pct: Double, velocity: CGFloat)。
- 绘制：Core Graphics 绘制背景条/缓冲条/已播放条；拖动中高亮、加粗以提升可感知度。
- 手势：UIPanGestureRecognizer，位置 x 映射为百分比，限制在 [0,1]。

4.3 PlaybackCoordinator

- 作用：
  - 对接 Cell 暴露的 UI 与回调（play/pause/seek/progress update）。
  - 拖动开始：暂停播放器、冻结 UI 高频回调；
  - 拖动中：只更新自绘进度，不频繁 seek；
  - 拖动结束：cancelPendingSeeks + 容差 seek（0.2~0.5s），seek 完成后若之前在播放则恢复。
- 仅有 active Cell 接收 15fps 进度回调，非 active Cell 不订阅或极低频。

4.4 PreloadManager

- 触发条件：当前播放 ≥ 60% 或 ≥ 1s；仅预一条；
- 方法：prepare(assetOf index: Int) -> Void；接口返回可取消的句柄，快速滑动时取消正在进行的预热。

- VideoFeedCell.swift

7) 详细实现任务拆分与优先级

高优先级：
1. 建立 VideoPlayerPool，保证只有一个 active AVPlayer（另一个 warmup 可选）。
2. 在 Cell 生命周期内统一 reset/attach/detach，消除状态污染与观察者泄漏。
3. 进度回调策略：active 15fps、拖动节流、不可见停止。
4. seek 并发防护：cancelPendingSeeks + 容差 + generationToken。

中优先级：
5. ProgressNode 自绘并替换 UISlider，统一视觉与交互细节。
6. 预加载策略（60% 或 ≥1s 触发），快速滑动取消。

低优先级：
7. 动画与微交互统一（layer-based transform/opacity，避免离屏）。
8. 监控完善（首帧/缓冲/失败率/功耗）。

8) 性能预算与验收指标

- 滑动性能：
  - 主流机型：> 55fps；低端机：> 45fps。
- 首帧时间（从可见到第一帧呈现）：
  - 降低 20%+（依赖 pool 与预热）。
- CPU/GPU：
  - 播放状态下 CPU 平均 < 35%，后台线程峰值平稳；
  - GPU stable，无大面积离屏渲染（Core Animation 工具验证）。
- 内存与泄漏：
  - Instruments 无增长趋势；观察者移除完整；
  - timeObserver 始终与 active Item 同步，切换立即移除。

10) 风险与缓解策略

- 风险：预热/attach 并发导致旧回调覆盖新状态。
  - 缓解：generationToken；attach 前统一取消旧回调与旧 token。
- 风险：自绘进度条的可访问性与手势冲突。
  - 缓解：实现 accessibilityValue/traits；对手势与父级滚动冲突做阈值判断（水平拖动判定）。
- 风险：设备差异（老机型）在 15fps 更新时抖动。
  - 缓解：可降级到 10~12fps；拖动时再升频。
- 风险：KVO 与 timeObserver 清理遗漏。
  - 缓解：ObserverCenter 统一管理，Cell 退出必经路径清理；单元测试覆盖。

# 结论先说

* **保留 AVPlayer**（硬解最佳），**统一 PlayerPool**（≤2 实例），**进度用自绘 Node**，**只对 active cell 订阅 15fps**……这些你已规划正确。
* 你的方案还缺少：**Texture 预渲染/预取的“范围调谐”**、**音频会话与中断策略**、**网络/缓冲的自适应参数**、**可见性/代际 token 的彻底竞态收口**、**动画与无障碍的小成本提纯**、**弱网/失败回退**、**可观测性与验收线**。把下面这些补齐，你会明显看到首帧、滑动 FPS、功耗的再下降。

## A. 列表与可见性（Texture 专项，强烈建议）

1. **ASRangeController“范围调谐”**
   把 Texture 的预加载/显示范围显式调优，让“+1/-1”屏提前布局与解码准备：

```swift
// 在 ShortsViewController
let tuningDisplay = ASRangeTuningParameters(leadingBufferScreenfuls: 1, trailingBufferScreenfuls: 1)
let tuningPreload = ASRangeTuningParameters(leadingBufferScreenfuls: 1.5, trailingBufferScreenfuls: 1.5)
collectionNode.setTuningParameters(tuningDisplay, for: .display)
collectionNode.setTuningParameters(tuningPreload, for: .preload)
collectionNode.leadingScreensForBatching = 1.0
```

> 这样 **Texture** 会在你滑到下一条前把节点布局/图片绘制好，主线程压力更稳。

2. **只保留 Texture，一个屏弃用 IGListKit**
   在这个页面里让 IGListKit 完全退出（避免 diff & range 控制器冲突），数据增量用你自己的 diff 或 Texture 自带的 batch updates。

## B. PlayerPool 再打磨（避免所有竞态）

3. **代际 token（generation）稳态化**

* 发起任何异步：`loadValuesAsynchronously`、`seek`、`attach` 前都**生成并携带 token**；回调里先比对当前 token。
* **timeObserver 只在 Pool** 一处持有，与 `currentItem` 绑定；cell 获得的是一个“弱引用闭包”，`detach` 时置空即可。

4. **主线程最小化 attach**

* `AVURLAsset(url:, options:)` 与 `loadValuesAsynchronously(forKeys:)` 在后台完成；**只在主线程做**：`replaceCurrentItem` 与 `layer.player = player`。
* 别在切 cell 时反复重建 `AVPlayerItem`：优先重用已准备好的 item（或 warmupPlayer 的 item）。

5. **中断与恢复**（易被忽略但影响真实体验）

```swift
// App 进入后台/来电/音频打断
AVAudioSession.sharedInstance().setCategory(.playback, mode: .moviePlayback, options: [.allowBluetooth, .interruptSpokenAudioAndMixWithOthers])
NotificationCenter...AVAudioSession.interruptionNotification { type == .began ? pause() : maybeResume() }
player.preventsDisplaySleepDuringVideoPlayback = true
player.allowsExternalPlayback = false
```

> 确保**打断后恢复**与**外放/车载**行为一致，不丢播放状态。

## C. 进度与拖动（顺滑/低功耗并存）

6. **进度驱动策略**

* active：`CMTime(value:1, timescale:15)`（≈15fps）；
* 拖动中：停掉 periodic observer，仅自绘；
* 非 active：不订阅或 1Hz（用于“灰条”缓冲显示即可）。

7. **seek 容差与竞争**

* 拖动预览阶段**不 seek**或最多低频“节流 seek”（≥120ms 一次）；结束时统一：

```swift
item.cancelPendingSeeks()
let tol = CMTime(seconds: 0.25, preferredTimescale: 600)
player.seek(to: target, toleranceBefore: tol, toleranceAfter: tol) { [weak self] finished in
  guard token == self?.token else { return }
  if wasPlaying { player.play() }
}
```

## D. 网络/缓冲自适应（弱网更稳）

8. **KTVHTTPCache 与 AVURLAsset 选项**

* 配置磁盘上限（3–5GB）+ LRU；
* `AVURLAssetOptions`：

```swift
let opts: [String: Any] = [
  AVURLAssetAllowsConstrainedNetworkAccessKey: true,       // 低数据模式仍可用
  AVURLAssetAllowsExpensiveNetworkAccessKey: true,         // 蜂窝允许
  AVURLAssetPreferPreciseDurationAndTimingKey: false
]
let asset = AVURLAsset(url: proxyURL, options: opts)
```

9. **动态缓冲与码率**

* `item.preferredForwardBufferDuration = networkIsPoor ? 8 : 4`
* `item.preferredPeakBitRate = cellular ? 2_000_000 : 5_000_000`（视素材设置）
* 失败重试：同源多码率时，**第一次缓冲>阈值**或`AVPlayerItemFailedToPlayToEndTime`→降码率重放。

---

## E. 动画与无障碍（免费性能）

10. **layer-based 动画**（transform/opacity）

* 点赞心形：常驻 `CALayer`，播放 `CASpringAnimation`，避免新建视图/重排。
* 禁用昂贵效果（大半径阴影/实时模糊）在滑动时段。

11. **手势冲突 & 可访问性**

* 进度条水平拖动采用**角度阈值**（与垂直滚动解耦）：`abs(tan(theta)) < 0.5` 才吃手势。
* 为自绘进度条补：`accessibilityTraits = .adjustable`、实现 `accessibilityIncrement/Decrement`。

---

## F. 守护与兜底（稳定性）

12. **资源失败与空时长兜底**

* `status == .failed || duration <= 0`：展示封面/错误态，**自动跳到下一条**，并上报。
* 长时间播放巡检：每 10 分钟收一次 `memory footprint` + file descriptors（Instruments 观察是否线性增长）。

13. **热/功耗自适应**

* 监听 `ProcessInfo.thermalState`：`>= .serious` 时把进度回调降到 10fps，暂停预加载。

---

## G. 可观测性（让优化“看得见”）

14. **os\_signpost 埋点**

* `scrollBegan → attach → itemReadyToPlay → firstFrame → play` 链路打点；
* 关键指标：**首帧耗时**、**缓冲事件/分钟**、**active 切换耗时**、**seek 成功率**。

15. **验收阈值（建议最终线）**

* 主流机型：滑动 **≥55fps**；低端 **≥45fps**。
* 首帧 < **300ms**（本地源），远程 < **500–700ms**。
* 单次滑动切片期间 **0 dropped frames**（以 Core Animation 采样为准）。

## H. 小片段（可直接套）

**Texture 预载 + active 判定**

```swift
func scrollViewDidEndDecelerating(_ scrollView: UIScrollView) {
  let page = Int(round(scrollView.contentOffset.y / scrollView.bounds.height))
  if page != activeIndex {
    // detach old
    oldCell?.didEndDisplay()
    activeIndex = page
    // attach new
    newCell?.willBecomeVisible()
  }
}
```

**仅 active 绑定进度**

```swift
pool.removePeriodicObserver()
pool.addPeriodicObserver(fps: 15) { [weak cell] time in
  guard cell?.isActive == true, let item = pool.currentItem else { return }
  cell?.progressNode.update(current: time.seconds, duration: item.duration.seconds)
```
